# P6-3 v2 secondary reliability freeze

**Status:** preregistered secondary reliability measurement; no paid/live execution authorized by this document  
**Parent execution freeze:** `docs/p6_3_v2_execution_parameter_audit.md`  
**Machine implementation:** `harness/src/p6/p6-3-v2-secondary-reliability.ts`

## 1. Purpose

P6-3 v1 exposed a measurement-reliability issue: `max_output_tokens` censoring can occur during mutation calls. The v1 observations motivate measurement of censoring and token usage, but they are exploratory only. This document fixes the v2 secondary reliability measurement before any v2 live data are collected.

These outcomes do not replace primary M or Rsem. They describe whether the execution envelope itself behaves differently across planned conditions and whether missing scientific observations are being generated by censoring.

## 2. All committed attempts are included

Secondary reliability summaries use **all committed scientific attempts**, including:

- successful scientific observations;
- semantic or protocol outcomes;
- deterministic or manually reviewed `infrastructure-invalid` replacement attempts;
- attempts belonging to a logical cell that later becomes `censored-exhausted`.

No valid-only filtering is permitted for censoring or token-usage summaries.

An uncertain in-flight attempt without a committed provider result is not silently treated as a zero-token or non-censored observation. It is reported separately through the runner's interrupted-attempt count and remains a `needs-audit` condition.

## 3. Per-attempt persistence

Every v2 attempt used by the unattended runner must persist a reliability envelope beside the original scientific artifact payload. The envelope contains:

- sequence, measurement, task, repeat, arm and attempt identity;
- provider-reported output tokens;
- provider-reported reasoning-output tokens where available;
- provider-reported input and total tokens as provenance where available;
- configured max output tokens;
- provider-derived incomplete reason where available.

The reliability wrapper rejects missing telemetry structure or malformed token values before an attempt artifact is committed. Each token field must exist explicitly; unavailable provider values are represented by `null`, not by omission or zero.

If automatic-infrastructure raw evidence is present, its output-token count, configured cap and incomplete reason must agree exactly with the reliability envelope.

The original scientific artifact is preserved inside the wrapped artifact rather than replaced.

## 4. Max-output censoring indicator and unclassifiable attempts

The secondary censoring indicator is intentionally distinct from the stricter `AUTO-INFRA-001` adjudication rule.

A committed attempt has:

```text
maxOutputCensored = true
```

when:

```text
executionStatus == response-incomplete
AND incompleteReason == max_output_tokens
```

It has:

```text
maxOutputCensored = false
```

when the provider state is classifiable and does not indicate the above max-output condition.

It has:

```text
maxOutputCensored = null
```

when censoring status cannot be classified from the persisted provider evidence, including:

- `response-incomplete` with no incomplete reason;
- a non-incomplete execution status carrying a non-null incomplete reason.

`null` is **not** interpreted as `false`.

`AUTO-INFRA-001` remains stricter for unattended adjudication: it additionally requires provider-reported output usage to equal the configured cap exactly. Therefore an attempt can be descriptively observed as max-output-censored while still requiring human audit because the evidence is insufficient for automatic `infrastructure-invalid` adjudication.

This definition is independent of arm identity and does not encode a special B1 rule.

## 5. Logical-cell outcomes

For every planned logical cell, the analyzer records:

- number of committed attempts;
- whether any committed attempt was max-output censored (`true / false / null`);
- attempts-to-valid-scientific-observation;
- whether the cell ended `censored-exhausted`.

Logical-cell censoring is:

```text
true  = at least one attempt is true
false = at least one attempt exists and every attempt is false
null  = no true attempt exists and at least one attempt is unclassifiable
```

A valid scientific observation for this secondary endpoint is the first committed attempt whose effective failure domain is one of:

```text
none / semantic / protocol / system
```

`infrastructure` and `other` do not count as scientific observations.

For terminal `completed` or `needs-design-audit` collection, every planned logical cell must have at least one committed attempt, and every cell must have either a scientific observation or a recorded exhaustion. Violations are integrity errors.

## 6. Arm-level censoring summaries

For each arm `B0/B1/B2/B3/B4/AF`, report:

- total committed attempts;
- censoring-classifiable attempt count;
- censoring-unclassifiable attempt count;
- max-output-censored attempt count;
- attempt-level censoring rate = censored attempts / censoring-classifiable attempts;
- attempted logical-cell count;
- censoring-classifiable logical-cell count;
- censoring-unclassifiable logical-cell count;
- logical cells with any max-output censoring;
- logical-cell censoring rate = cells with any censoring / censoring-classifiable cells;
- attempt-count distribution per attempted cell;
- attempts-to-valid-scientific-observation distribution;
- output-token distribution;
- reasoning-output-token distribution.

Unknown censoring states are therefore not allowed to inflate the denominator as if they were observed negatives. No arm is omitted because its value is zero.

## 7. M task x arm summaries

For M only, every task x arm combination is reported with the same distinction between total, classifiable and unclassifiable attempt/cell counts, plus censoring rates over classifiable denominators.

This is descriptive reliability analysis. It does not preregister a monotonicity test, a B1-specific test, a bimodality claim, or any other confirmatory arm pattern.

## 8. Token distributions and missing values

Token distributions report the sorted raw observed points plus:

- minimum;
- Q25;
- Q50;
- Q75;
- maximum;
- observed count;
- missing count.

Quantiles use the frozen rule:

```text
nearest-rank-q25-q50-q75-v1
rank(p) = max(1, ceil(p * n))
```

No mean is part of the preregistered primary reliability summary. This choice was made before v2 live data because the v1 exploratory run showed very large within-arm token variability, making means alone potentially misleading.

Missing provider token fields are not converted to zero and are not silently dropped: they increase the corresponding `missing` count.

## 9. Exhausted-cell reporting

Every `censored-exhausted` cell is listed by sequence, measurement, task, repeat, arm and attempt count without post-hoc removal.

This secondary summary does not relax the primary selection gate. As frozen previously:

```text
any exhausted logical cell
=> collection may finish
=> status = needs-design-audit
=> B_expose selection prohibited
```

## 10. Integrity gates

The analyzer/wrapper fails closed on at least:

- duplicate sequence/attempt identities;
- duplicate exhausted-cell identities;
- missing committed attempt artifact;
- wrong reliability-artifact schema;
- mismatch between state identity and artifact identity;
- missing required telemetry keys;
- malformed token telemetry;
- disagreement between AUTO-INFRA raw evidence and persisted telemetry;
- terminal collection containing an unattempted planned cell;
- terminal attempted cell with neither scientific observation nor exhaustion.

Ambiguous censoring evidence is represented as `null` rather than silently converted to an observed negative.

## 11. Offline verification before live use

`verify:p6-3-v2-secondary-reliability` constructs three planned logical cells with:

1. one censored attempt followed by a valid scientific observation;
2. three censored attempts ending in `censored-exhausted`;
3. one valid scientific observation with missing reasoning-token telemetry.

The verifier confirms all six attempt artifacts are persisted, four censoring events are counted, cell-level censoring and attempts-to-valid are correct, exhausted location is retained, missing token data remain explicit, quantiles follow the frozen nearest-rank rule, and artifact-identity / telemetry-evidence mismatches fail closed.

The implementation also exposes classifiable and unclassifiable censoring counts explicitly so later live adapters cannot silently treat missing provider reasons as non-censoring observations.

Paid/live P6-3 v2 execution remains blocked until this layer is wired into the actual v2 live executor/CLI and the final pre-live manifest binds the exact checkout and relevant hashes.
