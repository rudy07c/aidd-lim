# P6-3 v3 — PR C: fixed-environment Rsem executor

**Status:** implementation slice for review; no paid/live execution authorized  
**Depends on:** PR #38 Generation-0 binding builder, PR #39 v3 M executor pattern, PR #36/#37 fixed-environment runtime/provenance  
**Historical boundary:** `runRSemRepeat()` in `harness/p6-af-baseline-live.ts` and `executeP63RSemCell()` in `harness/src/p6/p6-3-live-executors.ts` remain unchanged.

## 1. Purpose

PR C adds the v3-only Rsem path without duplicating the historical Rsem parser/scorer/failure machinery.

```text
prebuilt run-fixed FixedEnvironmentBinding
        +
artifact evidence for one arm
        ↓
executeP63V3RSemCell(...)
        ↓
historical runRSemRepeat(..., injected clientFactory)
        ↓
request proxy adds E_fixed immediately before provider send
        ↓
historical schema / parser / scorer / failure semantics
```

The key seam already existed: `runRSemRepeat()` accepts a `P62ProbeClientFactory`. PR C uses that seam rather than editing or copying the historical runner.

## 2. What is intentionally changed

Only the model-facing evidence framing changes:

1. `FIXED ENVIRONMENT SPECIFICATION` is prepended as a separate section;
2. the historical `REPOSITORY FILES: ... QUESTIONS: ...` prompt follows byte-for-byte unchanged;
3. the top-level instruction is versioned for v3 and now explicitly permits both fixed-environment evidence and repository evidence.

The v3 instruction is necessary because the historical instruction says to use only repository evidence, which would contradict the newly introduced all-condition-common `E_fixed` channel.

The transformation is non-mutating: it derives a new request object from the historical request generated by `runRSemRepeat()`.

## 3. What remains historical

`runRSemRepeat()` remains the sole owner of:

- model and reasoning effort;
- max output tokens;
- timeout and retry policy;
- service tier / cache settings;
- the 12-probe bank supplied by the caller;
- structured-output schema;
- historical repository/probe prompt construction;
- provider error/refusal/incomplete handling;
- JSON parsing;
- forced-choice answer parsing;
- `scoreProbes()` semantic scoring;
- Rsem failure-domain and protocol-validity semantics;
- usage and cost accounting.

PR C therefore does not create a second Rsem scientific implementation.

## 4. Frozen PR-C interface contract

`executeP63V3RSemCell()` requires:

- `contextFiles`: arm-dependent artifact evidence only;
- `probes`: the frozen Rsem probe bank supplied upstream;
- `repeat`;
- `exposure`: existing artifact-only `P63ExposureEvidence`;
- `fixedEnvironment`: one prebuilt run-fixed `Readonly<FixedEnvironmentBinding>`.

The executor MUST NOT call `buildGenerationZeroFixedEnvironment()` or `createFixedEnvironmentBinding()`.

Generation-0 authenticity and exactly-once construction remain run-start responsibilities, not cell-executor responsibilities.

## 5. Budget separation

`E_fixed` remains outside `B_expose` / artifact exposure accounting.

PR C returns the caller's `exposure` unchanged. `fixedEnvironment.modelVisibleTokens` is recorded only as diagnostic/provider-input provenance and is never added to `budgetTokens` or `actualExposedTokens`.

## 6. Cell-level provenance

Every v3 Rsem cell records:

- `diagnosticSummary.fixedEnvironmentIdentity`;
- `diagnosticSummary.fixedEnvironmentModelVisibleTokens`;
- `artifactPayload.executorVersion`;
- `artifactPayload.promptVersion`;
- `artifactPayload.outputInstructionsSha256`;
- `artifactPayload.fixedEnvironment = fixedEnvironmentLogSnapshot(...)`;
- the exact historical `RSemProbeRepeatResult` as `artifactPayload.result`.

This prepares the later run-level gate that must prove one fixed-environment identity across M/Rsem, every arm, every repeat, and every generation in the treatment family.

## 7. Offline verifier

`verify-p6-3-v3-rsem-executor.ts` makes no provider call. It uses a fake `P62ProbeClientFactory` so the real historical `runRSemRepeat()` constructs the request and then traverses its real parser/scorer on a synthetic completed response.

The gate checks:

1. historical Rsem executor remains v2-only;
2. v3 Rsem consumes but never constructs `E_fixed`;
3. `runRSemRepeat()` remains the scientific owner (no duplicated scorer/parser);
4. historical timeout/retry contract reaches the wrapped client;
5. historical model/reasoning/output/schema/service/cache settings are unchanged;
6. v3 model-facing content is exactly `E_fixed` section + exact historical Rsem prompt;
7. a completed fake response traverses the real historical parser/scorer successfully;
8. artifact exposure remains unchanged by `E_fixed`;
9. exact fixed-environment identity/snapshot is persisted per cell;
10. builder/serializer run-start provenance remains outside PR C;
11. request transformation derives a copy rather than mutating the historical request object.

## 8. Explicit non-goals

This PR does **not**:

- modify historical `runRSemRepeat()`;
- modify historical `executeP63RSemCell()`;
- wire the Generation-0 builder into a run-start/calibration entrypoint;
- enforce cross-cell binding identity yet;
- add builder/serializer versions to run-level provenance;
- freeze the final blended selector, v3 budget grid, repeat count, or selection margins;
- authorize paid/live P6-3 v3 execution.

## 9. Next step after PR C

With PR A/B/C complete, the next slice is run-start wiring/provenance: build `E_fixed` exactly once from Generation 0, persist builder/serializer versions, feed the same binding to both v3 executors, and fail offline if any cell identity differs. Only after that should Candidate-D artifact-only selector re-audit/freeze and v3 calibration predeclaration continue.
